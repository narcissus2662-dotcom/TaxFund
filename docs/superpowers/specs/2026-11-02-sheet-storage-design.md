# ย้ายที่เก็บข้อมูลแอปกองทุนลดหย่อนภาษีไป Google Sheet

วันที่: 2 พ.ย. 2026
สถานะ: รอ Nate อนุมัติ

## ทำไมต้องทำ

แอปเดิมเก็บข้อมูลชุดเดียวไว้ใน localStorage ของ Chrome บนมือถือ ส่วน Supabase เป็นของเสริมที่ต้องตั้งเองทีละเครื่อง ปิดอยู่ก็ได้ และพังก็ไม่มีใครรู้ เดือน ต.ค. 2026 ข้อมูลในมือถือถูกล้าง (หลักฐานตรงกับการล้าง "คุกกี้และข้อมูลเว็บไซต์" ใน Chrome) ในขณะที่ Supabase แบบฟรีหยุดตัวเองไปตั้งแต่หลัง 11 ส.ค. ผลคือรายการซื้อช่วง ส.ค. ถึง ต.ค. หายไป และต้องกู้คืนจากอีเมลธนาคาร

ปัญหาอยู่ที่โครงสร้าง ไม่ใช่ที่ผู้ใช้ ผู้ใช้ไม่ควรต้องระวังเวลาล้าง Chrome

## เป้าหมาย

1. ทุกรายการที่บันทึกถูกเขียนลง Google Sheet ในบัญชี Google หลักของ Nate (บัญชีที่รับอีเมลธนาคาร) ก่อนที่แอปจะบอกว่าบันทึกสำเร็จ
2. ล้าง Chrome หรือเปลี่ยนมือถือแล้ว ข้อมูลไม่หาย เปิดแอปแล้วล็อกอิน Google ก็เห็นข้อมูลครบ
3. ไม่มีรหัสหรือ sync code ที่ผู้ใช้ต้องจำหรือเก็บเอง
4. ถ้าบันทึกไม่สำเร็จ ผู้ใช้ต้องเห็นชัดทันที
5. หน้าตาและการใช้งานเหมือนแอปเดิม คือโดนัทเป้าหมาย ยอดที่ต้องซื้อต่อสัปดาห์ถึง 30 พ.ย. ชิปเลือกกองทุน และรายการซื้อ
6. กู้รายการซื้อที่หายไปครั้งเดียว แล้วใส่ลง Sheet ตั้งต้น

## ไม่ทำ

- ไม่รองรับหลายเครื่องแก้ข้อมูลพร้อมกัน Nate บันทึกจากมือถือเครื่องเดียว
- ไม่ทำหน้า Sheet ให้อ่านง่าย Nate ไม่เปิด Sheet ดูเอง Sheet เป็นแค่ที่เก็บเบื้องหลัง
- ไม่ดึงข้อมูลจากอีเมลอัตโนมัติต่อเนื่อง การดึงจากอีเมลทำครั้งเดียวเพื่อกู้ข้อมูล
- ไม่บันทึกรายการขายคืน แอปนับเฉพาะยอดซื้อเหมือนเดิม
- ไม่ทำเรื่องขึ้นปีใหม่ แอปเดิมก็ไม่มี
- ไม่ใช้ Supabase อีก ส่วนจะลบโปรเจกต์หรือไม่ ให้ Nate ตัดสินภายหลัง

## สิ่งที่ห้ามเกิด แม้ระบบจะทำงานได้ในทางเทคนิค

- แอปขึ้นว่าบันทึกแล้ว ทั้งที่ข้อมูลยังไม่ถึง Sheet
- ข้อมูลตัวจริงยังอยู่ใน Chrome ที่เดียว แม้จะชั่วคราวก็ตาม ยกเว้นรายการที่กำลังรอส่ง ซึ่งต้องแสดงสถานะให้เห็น
- ใครก็ตามที่รู้ลิงก์ เข้าไปอ่านหรือแก้ข้อมูลได้
- ลิงก์ Netlify เดิมยังใช้บันทึกข้อมูลได้ ถ้ายังใช้ได้ Nate อาจเผลอบันทึกที่นั่นตามความเคยชิน แล้วข้อมูลจะไปอยู่ใน localStorage ที่เดียวอีก

## ข้อจำกัด

- Nate ไม่เขียนโค้ด ขั้นตอนที่ Nate ต้องทำเองต้องสั้น และเขียนเป็นภาษาไทยทีละขั้น แบบเดียวกับ `PF/PBS WebApp/DEPLOY_appscript.md`
- repo บน GitHub เป็นสาธารณะ ห้ามมีรหัส key หรือข้อมูลการเงินส่วนตัวในไฟล์ที่ commit (รวมถึงเอกสารนี้)
- เครื่อง Mac ไม่มี Node ใช้ clasp ไม่ได้ การนำโค้ดขึ้น Apps Script จึงเป็นการคัดลอกไปวางเองแบบ PBS WebApp
- ข้อความในแอปเป็นภาษาไทย ใช้ฟอนต์ Kanit และชุดสีเดิมตาม `CLAUDE.md` ของโปรเจกต์

## สิ่งที่ตัดสินแล้ว

### ที่เก็บและการเข้าถึง (Nate เลือก ทางเลือก A)
- ข้อมูลตัวจริงอยู่ใน Google Sheet ของบัญชี Google หลักของ Nate
- ตัวแอปย้ายไปอยู่ใน Google Apps Script web app ที่ผูกกับ Sheet นั้น
- Google เป็นผู้ยืนยันตัวตนให้ จึงไม่ต้องมีรหัสลับ
- **แก้ไข 2 พ.ย. 2026 (Nate สั่ง):** ให้บัญชีอื่นอีก 2 บัญชีเปิดแอปได้ จึงเปลี่ยนจาก Execute as = Me / Only myself เป็น Execute as = User accessing the web app / Anyone with Google account แล้วคุมสิทธิ์ด้วยการแชร์ Sheet แบบ Editor ใครไม่ได้รับแชร์ เปิดแอปแล้วจะอ่านเขียน Sheet ไม่ได้ (รายชื่ออีเมลอยู่ในหน้า Share ของ Sheet ไม่ใส่ไว้ใน repo)
- ผลข้างเคียงที่รับรู้แล้ว: คนที่ได้รับแชร์เห็นและแก้ได้ทุกรายการ เพราะยังไม่มีโหมดดูอย่างเดียว
- แอปคุยกับ Sheet ผ่าน `google.script.run` แบบเดียวกับ PBS WebApp

### การบันทึก (ผมเลือก)
- กดเพิ่มรายการแล้ว รายการขึ้นในรายการทันทีพร้อมสถานะ "กำลังบันทึก"
- เมื่อ Sheet ตอบกลับว่าบันทึกแล้ว สถานะจึงหายไป
- ถ้าบันทึกไม่สำเร็จ เช่น ไม่มีเน็ต รายการขึ้นสถานะ "ยังไม่ได้บันทึก" ชัดเจน เก็บไว้ในคิวในเครื่อง และลองส่งใหม่เมื่อกลับมาออนไลน์หรือเปิดแอปครั้งถัดไป
- ถ้ามีรายการค้างในคิว ด้านบนแอปต้องเตือนว่ามีกี่รายการที่ยังไม่ถึง Sheet
- การลบรายการ ตั้งเป้า และเพิ่มหรือลบกองทุนที่พิมพ์เอง ใช้หลักเดียวกัน คือถือว่าสำเร็จเมื่อ Sheet ยืนยันแล้วเท่านั้น
- ฝั่ง Apps Script ใช้ LockService ตอนเขียน กันการบันทึกซ้อนกัน
- ทุกรายการมี id ที่แอปสร้าง เพื่อให้การส่งซ้ำตอนลองใหม่ไม่ทำให้ได้รายการซ้ำ

### ปุ่มล้างข้อมูลทั้งหมด (ผมเลือก)
- ตัดปุ่มล้างข้อมูลทั้งหมด (`resetBtn`) ออกจากแอปใหม่ เพราะเมื่อ Sheet เป็นที่เก็บตัวจริงชุดเดียว ปุ่มนี้คือทางลบข้อมูลจริงทั้งหมดด้วยการกดครั้งเดียว ซึ่งขัดกับเป้าหมายของงานนี้
- ลบทีละรายการได้เหมือนเดิม ถ้าต้องการเริ่มใหม่จริง ๆ ให้ทำใน Sheet ซึ่งมีประวัติการแก้ไขให้ย้อนกลับได้

### การเปิดแอป (ผมเลือก)
- ข้อมูลที่เห็นทั้งหมดมาจาก Sheet
- อนุญาตให้เก็บสำเนาไว้ในเครื่องเพื่อให้หน้าแรกขึ้นเร็ว แต่ต้องแสดงว่ากำลังโหลดข้อมูลล่าสุด จนกว่าจะได้ข้อมูลจาก Sheet
- ถ้าโหลดจาก Sheet ไม่ได้ ขึ้นเตือนชัดเจน

### ลิงก์ Netlify เดิม (ผมเลือก)
- เปลี่ยน `index.html` บน Netlify ให้เหลือแค่หน้าแจ้งว่าแอปย้ายไปแล้ว พร้อมปุ่มไปลิงก์ใหม่
- หน้านี้ไม่มีช่องบันทึกข้อมูล และไม่อ่านหรือเขียน localStorage

### การกู้ข้อมูลครั้งเดียว
- ผมสร้าง Sheet ในบัญชี Google หลักของ Nate (บัญชีที่รับอีเมลธนาคาร) แล้วใส่ข้อมูลตั้งต้นให้
- แหล่งข้อมูล: สำเนาบนคลาวด์เดิม อีเมลยืนยันคำสั่งซื้อจากธนาคาร PDF ที่แนบมากับอีเมลแจ้งเตือน (Nate พิมพ์รหัสเปิดไฟล์เองในหน้าต่างของ Mac) และ statement รายไตรมาสจากนายทะเบียนกองทุน ยอดสุดท้ายตรงกับแอปธนาคารทั้งสองแห่ง (Nate ตรวจแล้ว)
- **สถานะ 2 พ.ย. 2026: กู้ข้อมูลครบแล้ว และ Nate ตรวจรายการแล้ว** ข้อมูลอยู่ในไฟล์ `recovered-data-2026-11-02.json` ซึ่งตั้งไว้ไม่ให้ขึ้น git (`.git/info/exclude`) แต่ละรายการมี `source` บอกว่ามาจากแหล่งไหน
- ชื่อกองทุนที่ใช้: แปลงรหัสย่อและชื่อเต็มจากเอกสารธนาคาร เป็นชื่อที่แอปใช้ตามที่ Nate ยืนยัน รายชื่ออยู่ในไฟล์ข้อมูลที่กู้มา ไม่ใส่ไว้ใน repo
- รายการขายคืนและการสับเปลี่ยนระหว่างกองทุนไม่ใส่ เพราะแอปนับเฉพาะยอดซื้อ
- เมื่อข้อมูลครบแล้ว แอปใหม่จึงเปิดใช้ได้ทันทีพร้อมข้อมูลครบ ไม่ต้องมีป้ายแจ้งว่าข้อมูลยังไม่ครบ
- ตัวเลขจริงจะไม่อยู่ในเอกสารนี้หรือไฟล์ใด ๆ ใน repo

## โครงสร้าง Sheet

แท็บ `Purchases` หัวคอลัมน์แถว 1:

| คอลัมน์ | ความหมาย |
|---|---|
| id | id ที่แอปสร้าง ห้ามซ้ำ |
| date | วันที่ซื้อ รูปแบบ YYYY-MM-DD |
| fund | ชื่อกองทุนตามที่แสดงในแอป |
| amount | ยอดเงินเป็นบาท |
| createdAt | เวลาที่บันทึก |

แท็บ `Settings`: เป้าหมายทั้งปี และรายชื่อกองทุนที่ผู้ใช้พิมพ์เอง (`customFunds`)

ตำแหน่งเซลล์และรูปแบบการเก็บภายในแท็บ `Settings` ให้ผู้สร้างตัดสินเอง

## ไฟล์ในโปรเจกต์

- `apps-script/Code.gs` ฝั่งเซิร์ฟเวอร์ (doGet และฟังก์ชันอ่านเขียน Sheet)
- `apps-script/Index.html` ตัวแอป ดัดแปลงจาก `index.html` เดิม ตัดส่วน Supabase นำเข้า และส่งออกทิ้ง
- `apps-script/DEPLOY.md` ขั้นตอนภาษาไทยให้ Nate นำโค้ดขึ้น Apps Script และ deploy
- `index.html` กลายเป็นหน้าแจ้งย้าย
- `CLAUDE.md` อัปเดตให้ตรงกับโครงใหม่

## บัญชี Google และการแจ้งเตือนเรื่องสิทธิ์

ตอนออกแบบ Chrome บนมือถือของ Nate ล็อกอินไว้บัญชีเดียว และ PBS WebApp ใช้งานได้ ภายหลังเปลี่ยนการ deploy เป็น Execute as = User accessing ตามหัวข้อ "ที่เก็บและการเข้าถึง" ด้านบน

แอปต้องแยกข้อความผิดพลาดให้ชัด 3 แบบ คือ "ไม่มีเน็ต" (ลองส่งใหม่เอง), "บัญชีนี้ไม่มีสิทธิ์ใน Sheet" และ "ต้องกดอนุญาตสิทธิ์ใหม่" สองแบบหลังห้ามลองส่งซ้ำอัตโนมัติ ส่วนรายการที่ Sheet ปฏิเสธถาวร (ข้อมูลผิดรูป) ให้นำออกจากคิวและแจ้งผู้ใช้ ไม่ให้ขวางรายการอื่น

## ส่วนที่ยังไม่แน่ใจ ต้องเช็กตอน deploy จริง

- แถบข้อความของ Google ด้านบนแอปอาจไม่ขึ้น ถ้าเจ้าของสคริปต์เป็นคนเปิดเอง
- ไอคอนบนหน้าจอโฮมของ Android: PBS WebApp เคยเจอว่าตั้ง XFrameOptionsMode เป็น ALLOWALL แล้วได้ไอคอน G แทน ให้ใช้ค่าเริ่มต้นตาม PBS

## ส่วนที่ให้ผู้สร้างตัดสินเอง

- รูปแบบเก็บคิวรอส่งในเครื่อง และจังหวะลองส่งใหม่
- หน้าตาของแถบเตือนและสถานะรายการ ให้อยู่ในชุดสีและฟอนต์เดิมของแอป ไม่ใช้ emoji เป็นไอคอน
- วิธีทดสอบฝั่ง JavaScript บนเครื่อง Mac ซึ่งไม่มี Node แต่มี JavaScriptCore

## ตรวจว่าเสร็จจริง

1. บันทึกรายการจากมือถือ แล้วเห็นแถวใหม่ใน Sheet
2. ล้าง "คุกกี้และข้อมูลเว็บไซต์" ใน Chrome แล้วเปิดแอปใหม่ ล็อกอิน Google แล้วเห็นข้อมูลครบ
3. ปิดเน็ตแล้วบันทึก แอปขึ้นสถานะยังไม่ได้บันทึก พอเปิดเน็ต รายการถึง Sheet เองโดยไม่ซ้ำ
4. เปิดลิงก์ web app จากบัญชี Google อื่น แล้วเข้าไม่ได้
5. ลิงก์ Netlify เดิมเหลือแค่หน้าแจ้งย้าย
